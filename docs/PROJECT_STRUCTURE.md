# Flex CMS project boundaries

This document defines which files are authoritative source, which files are
required at runtime, and which files may only be generated while building a
release.

## Source of truth

- PHP application source: `src/`, `contracts/`, `config/`, `database/`, `bin/`.
- Admin frontend source: `resources/admin/`.
- Server-rendered templates: `resources/views/`.
- Public brand assets: `public/assets/brand/`.
- Automated verification: `tests/` and frontend test files under `resources/admin/`.
- Project metadata: `composer.json`, `composer.lock`, `platform.json`, `phinx.php`.

Generated files under `public/build/`, frontend `dist/`, `node_modules/`,
Composer `vendor/`, caches, logs, releases and installed website copies are not
authoritative source.

## Development-only files

- `resources/admin/node_modules/`
- `resources/admin/dist/`
- frontend TypeScript, ESLint, Prettier and Vite configuration
- PHPUnit, PHPStan and PHP CS Fixer configuration
- Docker and Compose configuration
- tests and local caches

Development files must not be copied into a platform release.

## Runtime files

- PHP application source and configuration
- Composer production dependencies
- database migrations
- server-rendered templates
- public entry point and static brand assets
- production frontend assets generated during the release build

Writable runtime data remains outside platform packages: `.env`, `storage/`,
`plugins/`, `themes/` and `public/media/`.

## Production artifacts

The `plugins/` directory is an installation directory and is not part of the
platform source tree. Only `plugins/.gitkeep` is tracked by the platform
repository. Each plugin should be developed and versioned in its own Git
repository, then installed here as a package, ZIP release or deployment
artifact.

- Production frontend assets are generated by the frontend `build` command.
- Minified JavaScript and CSS are production artifacts, never editable source.
- Platform ZIP files are generated from a clean staging directory.
- Release staging must exclude `.git`, `node_modules`, frontend source,
  development configuration, tests, caches and user-managed runtime data.

## Repository rules

- The repository has exactly one Git root.
- Dependencies and generated build output are ignored.
- Source assets are readable and non-minified.
- A platform package is created only after backend and frontend checks pass.
