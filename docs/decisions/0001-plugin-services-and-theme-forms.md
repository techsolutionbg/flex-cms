# ADR-0001: Публични услуги за плъгини и декларативни полета от тема

Статус: прието за локалната реализация. Дата: 11.10.2026.

## Контекст

Flex Contact Forms трябва да работи без други плъгини, с теми на PHP и Twig. Полетата от темата трябва да се валидират при POST дори когато темата не е рендерирана в тази заявка. Extension API v1 досега предлага lifecycle, routes, admin UI и assets, но не стабилен достъп до storage, mail, CSRF и активната тема.

## Решение

PluginContext има нов незадължителен параметър `services`, така че старите конструкторни извиквания работят. PluginServicesInterface предоставя ограничен достъп; storage.documents, mail.send и theme.extensions са permissions с default deny. Lifecycle и request boot използват една и съща factory. Услугите не изпълняват работа в конструктора и не изискват старите плъгини да приемат нови методи.

Хранилището е обща таблица extension_documents с композитен ключ plugin_id/document_key. Това заменя предложението за четири специфични таблици за първа версия: избягва предоставяне на SQL/вътрешния ORM като публичен API и позволява транзакционно записване на запитване, idempotency и outbox. Mutex ред сериализира транзакциите на един плъгин, включително конкурентно създаване на нови ключове. Пагинацията работи върху ключове. Компромисът е ограничени възможности за филтриране и по-ниска пропускателна способност при много запитвания; при нужда се добавя публичен query/storage договор с миграция, вместо директна зависимост от ядрото.

Темата посочва JSON descriptor чрез theme.json.extensions[plugin-id]. Resolver проверява version=1 и границите на realpath. Schema merge е в плъгина, който познава полевия договор. Шаблонът заменя само вътрешното представяне, а wrapper/security controls остават в плъгина. При невалидни полета формата се блокира; при проблем с визуален шаблон се използва fallback.

Общи hooks public.extension.render и http.response позволяват съответно theme helpers и private/no-store политика за страници с анонимен CSRF. extensions:maintain стартира callback-и само на активни плъгини и не вкарва контактна логика в основната платформа.

## Последствия

Необходима е нова локална версия на платформата 0.1.64 и миграция преди инсталация на плъгина. Други плъгини не се променят. Плъгинът остава отделно Git хранилище и не влиза в platform ZIP. Старите API конструкторни тестове остават валидни.

Outbox доставката е at-least-once; SMTP не предоставя exactly-once гаранция. Cron трябва изрично да се конфигурира на хостинга. Uninstall запазва документите, защото няма изрично избран режим за унищожаване на потребителски запитвания. SMTP грешките пазят delivery status без secrets; подробната инфраструктурна диагностика остава в mail transport/hosting логовете.
